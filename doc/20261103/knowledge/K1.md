# K1. Business Vocabulary & Ontology

关联 Skills：S1、S2、S3、S4、S5、S6、S8。

## 业务背景与基础知识

本文件提供理解访谈所需的战略背景、术语和地域口径。具有明确适用时期的资料只解释对应语境，不替代本轮事实；具体业务判断方法见[业务逻辑知识库](K2.md)。

**这份背景要帮助读者建立一幅业务图景：** 顾客因产品、健康或生活需求参与；伙伴通过体验、分享与服务开展经营；有些人进一步承担组织与带教工作；公司与 AM 提供方向、资源和支持。具体材料中，谁承担哪项工作、取得什么结果，仍需要分别确认。

学习顺序：**人和角色 → 日常业务与支持关系 → 指标与职级 → 地域与业务网络 → 战略背景 → 历史资料的使用。** 前五部分建立共同语言，历史画像帮助提出比较问题；历史访谈的解释方式见[推理习惯](../skills/S3/SKILL.md)。背景说明概念之间是什么关系；业务逻辑知识库进一步说明怎样用实际材料作判断。


第一次阅读，不必先记住所有英文缩写和职级。先理解人、动作和支持之间的关系；遇到指标或角色名称时，再用对应章节核对。地域目录是查询数据，正文说明怎样理解和使用它。历史战略、画像和人员讨论语境都带有原适用时期，不会因放在 context 中就变成本轮事实。

本文件集中维护已有业务概念、角色、战略时期、指标与地域知识。复杂的判断方法放在 Reasoning；历史访谈如何理解、怎样避免给人员固定权重，见[原始信息处理](../skills/S3/SKILL.md)。

## 1. 先认清人：身份、需求与实际角色

先看“这个人以什么身份参与、希望得到什么、实际做什么”。三者描述不同方面，不能从其中一个直接推断另外两个。

### 正式身份与实际行为

- PC（Privileged Customer）是优惠顾客，SR（Sales Representative）是销售代表。正式身份、购货、活跃、经营意愿、带人能力分别判断。

### 顾客价值与经营价值怎样同时存在

C 描述顾客视角，关注产品体验、健康、生活方式与个人改变；B 描述经营视角，关注服务顾客、组织活动和带动伙伴。“B/C 同体”说明同一个人可以同时重视两种价值，不是两个互斥的正式身份。

“B 进来，C 起步”描述一种实际路径：即使带着创业意愿加入，也可以先从自身体验和需求开始，再学习服务他人。另一部分人希望持续消费或分享，并不选择经营。理解材料时，先明确当时在讨论哪一种需求与动作。

### 分享、运营与带教分别是什么工作

| 名称 | 主要说明什么 | 与相邻概念的关系 |
|---|---|---|
| KOC（Key Opinion Customer） | 从真实使用与生活改变出发分享体验 | 分享可以促成交流，但不等于已经承担日常运营或具有经营意愿 |
| 主理人、小群主 | 组织内容与活动，维持互动，承接后续联系 | 同一个人可以也是 KOC；组织工作与分享工作仍要分别辨认 |
| 经营骨干、市场领导人 | 承担服务、经营、带动伙伴或更大范围的组织与培养 | 看实际责任；称呼和职级不能代替具体能力 |
| AM（Account Manager，业务发展顾问） | 公司支持侧，诊断问题、匹配资源、共创和示范陪跑 | 与市场协作；不能把员工完成的工作直接算作伙伴已具备的能力 |

访谈里“腰部”强调承上启下、借力并支持基层；“高阶”强调更大范围的方向、组织与人才责任。它们是理解实际责任的相对说法，不能固定等同某个职级、积分或收入档。

例如，一个人已购货、愿意分享使用体验，但尚未组织活动，可以分别理解其消费行为与 KOC 参与；不用因为他没有当群主就判断成长失败，也不能因其分享积极就认定已成为独立经营者。

**衔接下一部分：** 人与角色清楚后，再看这些人怎样在日常经营与共同支持中配合。

## 2. 再理解业务：接触、服务与能力成长怎样连接

日常经营同时包含顾客关系和伙伴成长。前者关注人为什么来、怎样获得价值、为什么继续参与或购买；后者关注谁来服务、怎样学会运营，以及怎样帮助别人也能做。

### 从一次接触到持续关系

访谈会用下列词概括具体动作。这里保留原有术语与定义的对照，帮助读懂材料；不把它们重新设为业务分析文件的分类框架。

| 访谈中的说法 | 对应的具体含义 |
|---|---|
| 开口（entry points） | 创造与人接触和交流的入口，不只指开口说话，也不等于已经注册、购买或留存 |
| 链新 | 首次接触之后，持续链接新人、建立关系；与接触到了多少人分别判断 |
| 破圈 | 接触原有熟人圈和存量人群之外的人；活动形式变新，不自动说明人群已扩大 |
| 吸留转培（attract / retain / convert / develop） | 吸引接触、留住参与、发生转化、培养能力。动作可以交错，“转”可能指购货、分享、KOC参与或经营，按本次原文确认目标 |
| 浸泡（immersive community engagement） | 通过持续体验、交流、分享和陪伴逐步建立理解与信任；进群、停留或反复收资料不能单独证明这一过程已完成 |

个人分享、兴趣活动、健康话题和线上内容都可能创造接触机会。首次接触之后，由谁继续联系、邀请参加什么、提供怎样的体验与服务，决定这段关系怎样被承接。持续体验与陪伴常被称为“浸泡”，重点是其中的交流、体验、分享和信任建立，不是单纯在群里停留。

吸引、留住、转化和培养是理解这些动作的过程视角。“转化”可能指购买、分享或经营，“培养”可能指服务、运营或带教能力；先确认材料中的具体目标。动作会交错发生，不是所有人都必须依次成为消费者、KOC、经营者和领导人。

注册建立身份，购货是购买行为，续约延续相应身份，持续参与体现互动，经营与带人则涉及另外的责任。听到“新人留下来了”时，需要继续理解留在什么活动、保持什么行为。

### 日常社群与共同平台怎样配合

### 社群、平台及参与环境

- 小齿轮 ABO-led communities：伙伴自己运营的基层社群，是接触、服务、体验和练习的日常载体。
- 大齿轮 organization-led platform：组织层面的共同平台，汇聚方向、活动、学习或资源。大小主要指组织作用，不只指人数；不能默认大齿轮就是总部。
- 中平台 content hub：连接基层实践与组织支持，可能包含内容、交互、学习、实操与培养。主体可以是市场领导人或公司支持，形式可以线上或线下，不是固定软件产品或正式组织层级。先辨认谁建、服务谁、做什么。
- 场域 environment / atmosphere：让人愿意参与、体验、互动、分享并得到反馈的环境，包含关系与运营方式，不仅是场地。

伙伴自己的社群通常承载具体服务与练习；共同平台可以汇集内容、讲师、活动或学习机会，支持多个社群。两者可以相互借力：伙伴带着真实问题获得示范，再回到自己的顾客与活动中实践。这里说明可能的工作关系，不代表每个市场都已经建立了完整承接。

### 培养、复制与公司支持怎样衔接

培养把真实任务与示范、练习、反馈连接起来，使伙伴逐渐独立。带教进一步帮助别人理解并完成工作；复制关注其他伙伴能否学会并持续使用方法，而不只看同一活动是否再次举办。架构、腿、前排描述业务关系与人才结构，结构本身不证明其中的人已具备能力。

公司与 AM 可以提供公共资源、诊断、示范和陪跑；领导人与伙伴承担的日常服务、运营和培养，要按当地实际分工确认。资源提供、资源被使用、伙伴学会，以及市场能够自主持续运行，是不同进展。公司支持与市场自主也可以并存，不以公司完全退出作为唯一结果。

**衔接下一部分：** 理解了动作与责任，才知道各项指标究竟在记录哪一部分业务。

## 3. 看懂指标：金额、积分、资格与行为各说明什么

先辨认指标对象与单位，再理解名称。销售结果、购货规模、经营资格和实际能力描述不同方面；同一个人可能同时被多个指标记录，不能把它们当作可相加的人群。

### 术语及正式映射

- BV = 净营业额 / Business Volume；PV = 销售指数（积分额）/ Point Value；PPV = 个人/商户销售指数；GPV = 业绩指数；APV = 国内进修指数；TP = 海外进修指数。金额、积分、人数、比率不可混用。
- 常见职级译名：营销之星 Sales Star/Q，菁英创客 Bronze，营销助理 Silver Producer，营销主任 Gold Producer，高级营销主任 Platinum，营销经理 Emerald，高级营销经理 Diamond。职级译名用于理解，不据此推导政策资格。
- Q 在术语表可指 Sales Star 或 qualify；Q 月数、Q3、Q12 必须结合语境与适用政策，不能统一展开。BFI、BBI 等缩写或门槛不明确时查正式资料，保留未知。

### 把指标放回具体业务动作

销售额描述一定时期与范围的销售结果；购货户数描述发生购买的规模；生产力需要明确由哪类对象产生、采用金额还是积分；续约率需要明确谁应续约、何时续约。具体定义和分母按对应正式资料，不用一个泛称代替不同口径。

职级说明制度下的资格与结果，服务、运营与带教能力则看实际行为。例如，本人已达标且能稳定服务顾客，可以保留这两项进展；能否教出下一位经营者，还需相应观察。进一步的指标组合与判断见[业绩形成与增长质量](K2.md)。

**衔接下一部分：** 同一指标还必须有清楚的范围；地域范围与推荐关系描述的是两种不同组织方式。

## 4. 分清范围：地域划分与业务网络不是一回事

地域目录帮助统一名称，业务网络帮助理解人与人的经营关系。分析既要知道资料来自哪里，也要知道实际讨论的是哪一个市场或群体。

- 城市、城市群、片区/大群、营运区是不同层级。LOS（Line of Sponsership，源表拼写）表示市场归属和推荐关系，与地域划分不同；业务网络可以跨地域。
- 本包 [地域目录](data/geography-catalog.json) 保留历史正式地域映射，只有需要地域归一时读取；其中负责人或文件名可帮助理解材料范围，不能证明每句话的地方归属。不把“北京营运区”当“北京城市群”，不把片区全体城市群赋给每个问题。

### 怎样阅读地域目录

| 目录字段 | 阅读时的作用 |
|---|---|
| name | 正式城市群名称，用于统一地域表述 |
| operatingRegion / operatingOwner | 对应营运区与负责人，不等于同名城市的当地市场 |
| area / areaOwner、group / groupOwner | 原表记录的片区或大群及负责人；按实际有值字段解释，不自行补齐空项 |
| sourceFile、sourceHash、sheet、row | 追溯原始映射来源与行位置，不是业务判断或访谈证据 |

例如，某负责人在片区讨论中引用另一地区的案例，反馈来源与案例发生地就可能不同；不能把案例自动分给该片区的全部城市群。一位领导人的 LOS 网络跨城市经营，也不能仅凭其主要所在地把所有顾客和团队归到同一个城市群。

本目录保留的是历史映射。新一轮如果提供适用时期更新的正式资料，按新资料核对；不通过修改旧目录来猜测当前人员或地域变化。

**衔接下一部分：** 概念、指标与范围明确后，再看战略文件为什么关注这些业务关系。

## 6. 使用历史画像：把分型变成问题，不把标签当答案

### 用历史分型提出问题

历史 PF21–PF26 画像参考分为 A“成熟先锋大群（生产力回落）”、B“平稳守成型（人数持平·续约短板）”、C“新人收缩型（续约质量低·生产力上坡）”、D“增人不增效型”。这是特定数据和时期的聚类，类型名称是概括，组内各城市、各时期可能并不符合名称里的每一项描述，不能永久绑定城市群。

看到“人数持平、续约短板”等分型，可以据此提出要核对的问题：哪些人延续身份、哪些人实际购买，近期情况是否仍与历史相同。答案应回到本轮资料；即使曲线相似，也要继续确认具体人群、动作与条件。

历史画像提供的是比较起点，不是原因诊断。同一类型内可能有不同业务网络和客群，不同类型也可能遇到相似的服务或培养问题。由此进入 Reasoning 分析时，带着问题核对，而不是带着标签归类。

## 来源文件与片区／大群的确认映射

地域归属由上传文件名、受访者身份、材料内容和正式地域目录共同核对，不仅搜索正文地名。片区／大群层级的反馈可向上汇总到营运区，不自动分配到下属城市。正式大群按[地域目录](data/geography-catalog.json)中的 group 登记为中间选择层；不因没有 area 就跳过大群。
