# S1. Evidence Extraction & Classification

## Purpose
证据提取与分类。连续阅读本轮全部原稿，登记真实连续区间和解析失败处。Step 0 保留原段号、原文和标准化文本的映射；清理噪音不得更改对象、数字、否定、条件及计划／实施状态。逐信息点区分事实、态势判断、受访者归因、分析推断、痛点、实践、效果、明确需求。主持人的问句不当作答复。同一原稿及其合并稿只算一个独立来源。Speaker 无法核实时留空，不能把文件负责人当作每句话的发言者。

### 先完整阅读并保留重要信号

##### 通用方法的共同说明

这套通用方法涵盖材料来源、完整阅读、理解与推断、形成判断、综合取舍、引用和表达。[业务逻辑知识库](../../knowledge/K2.md)说明具体业务关系；业务推理、质量检查 和 报告规范 分别支持判断形成、证据核查与清楚表达。

跨模块共同覆盖材料依据、完整阅读、发言理解与推断边界、业务判断、综合与范围、原文来源、清楚表达及定稿核对。它们分别由相关工具、质量检查 和 报告规范 承担，不构成另一套分析步骤。

这份文件教的是：怎样把已经读到的信息变成有依据、容易理解的判断。阅读材料、作出解释、决定重点、引用原话和写成正文，是相连但不同的工作。不要只检查引文是否真实，也要检查正文是否解释了这些材料共同说明什么。

以下几个常用说法，在本文件中有明确含义：

| 说法 | 具体意思 |
|---|---|
| 完整覆盖 | 重要信息都经过考虑，并有合适去向或不纳入理由；不是把每句话都展示出来 |
| 综合判断 | 解释多个观察共同说明什么，同时保留会改变结论的差异；不是将摘要再缩短一遍 |
| 机制解释 | 说明某个因素通过哪项具体动作影响结果；合理解释仍需区分已知与推断 |
| 支持取舍 | 说明应维持、补充、调整或先验证什么，以及为什么；不是把每项诉求都列为高优先级 |
| 范围与条件 | 交代判断适用于谁、哪里、什么时期和什么情形；只保留真正影响理解的限定 |
| 校准例 | 帮助学习怎样判断、分类或表达的例子；不能当作当前材料已经发生的事实 |

##### 阅读与信息处理的输入、产出和协作

本模块处理原始访谈中的信息，不先替每份材料定结论。

| 模块说明 | 具体内容 |
|---|---|
| 输入 | 本轮完整原始访谈、用户分析目标、必要业务背景。 |
| 如何处理 | 结合上下文辨认观察、解释、预测、请求和实践；记录对象、时期、真实位置与差异，保留重要少数和反例。 |
| 产出 | 可回查的信息与简短覆盖记录。按工作流契约保存结构化信息及真实定位。 |
| 与其他模块的关系 | 信息交给业务分析和需求萃取；事实与范围要求同时执行 质量检查。 |

这些说明让分析方法可讨论、可调整，不设条目配额；工作流按数据契约保存实际中间产出。

##### 完整阅读与覆盖

这一部分解决两个问题：有没有读到完整上下文，重要信息有没有在综合时丢失。先理解全文，再决定重点；主线清楚和保留重要少数、反例需要同时做到。

#### 阅读全文并结合上下文理解

先列明本轮原稿清单，以简短内部记录逐文件保留总页数／段落数／行数等可核对边界、已实际阅读的连续区间及未读或解析失败区间。长文件分批读取；工具输出被截断、仅提取成功或检索命中均不算已读，须缩小批次补读。确认从开头到末尾无缺段，表格等承载业务内容的部分均已读，才记为读完；只看末尾不算全文覆盖。中断或上下文切换后从未读处继续。记录只保留阅读状态与来源定位，不要求披露内部思维过程。

无论输入几千字还是几十万字，分析必须覆盖本次每一份相关访谈的完整内容。不要只依据文件开头、结尾、目录、摘要或搜索命中片段；材料中间的追问、修正、实践细节和反例与首尾同样重要。

先读全，再决定主线。可自由选择分批、笔记或其他处理方式；阅读中形成的主题和解释都只是候选，在完成本轮分析范围内全部材料阅读前，不将其定为最终分析框架，也不据此筛掉后续信息。报告的四个部分与二层分类是展示框架，不是预先确定的业务结论；读全后依据整体材料决定主线，必要时重组或放弃初步主题。

座谈常从整体业务走势进入新人、骨干、领导人、健康焕龄及赋能讨论；不同对象和层级可能在同一文件反复出现，也可能在后文推翻前面的笼统表达。结合完整对话理解：第一次说“缺案例”，后文澄清“案例不少，但基层看不到第一步”，报告应采用澄清后的需求；同时保留前后差异的解释。主持人的问题不是受访者已经认可的事实，假设问法也不是实际结果。

归纳后仍须辨认对象、具体动作、原因的提出者、已有回应、结果、时期和适用条件。完整阅读不等于全文展示：资料依据只保留支撑当前判断的相关原文，清理语气词、口头重复、寒暄和无关插话，保留具体信息、例子、有意义的表达及关键限定。

可理顺语序，无需逐字保留每个措辞，但不能变成分析总结或改变对象、数字、条件、否定和实施状态。Evidence 卡片直接展示清理后的内容，不加“节选并清理口头重复”“跨段节选”“说话人1”等标记；文件名和各实际段落定位保留。

具体规则见选取相关原话并保留限定。

同一发言在原稿、合并稿或摘要中重复出现时，只作为一份证据，不增加独立支持数量。不能因后文更具体或某观点低频就丢掉重要少数与相反证据。没有读到、未能解析或超出本轮可处理范围的内容要如实说明；局部分析不能包装成全量报告。不凭印象猜人数、发言频次或支持比例。

用与阅读方式相适应的简短内部记录保留重要业务信号、真实定位与范围、解释身份、最终主／子判断或需求去向。综合时特别检查不同人群的约束、地方独有但重要的需求、正向反例及计划与实际结果的区别；即使只出现一次，只要会改变判断或支持取舍就保留。

只有原文引用而没有相应业务解释，不算已覆盖。具体规则及成稿后的材料反查见[分析质量规范](../../knowledge/K5.md)，无须重复摘录，也不在 HTML 增加覆盖表。

#### 记录重要信号并检查遗漏

对每份原稿分别检查五类信号：经营走势与指标口径；不同人群在开口、留存、经营、带教中的受阻动作；已做措施、实际反馈与未达到的结果；不同层级的明确支持请求；反例、地方独有事项及计划／预测与实际的差别。未发现时不编造，也不以其他文件已有同主题代替检查。每个重要信号须定位到最终实际可读的正文、Reasoning 或具体需求中的业务解释；不纳入则记录业务理由。主题词、宽泛 Insight 关联、引文或隐藏字段不算覆盖，不设 Insight 数量下限。

沿用阅读笔记维护简短的内部覆盖记录，工作流按数据契约保存中间产出；报告正文不展示内部阅读核查日志。阅读时先保留有潜在业务价值的信号及真实定位、对象、时期、解释身份与相反信息；读全后才确定主线。重要性看业务后果、独立机制、不同支持选择、关键例外与明确需求，不按词频、发言人职级或预期条目数筛选。不要等主线写好后才记录“支持主线”的材料。

综合时逐项决定重要信号的去向，而不是给一个段落范围贴主题名。一个段落同时含计划、使用反馈和供给缺口时，分别处理其业务含义；合并稿与原稿重复不增加支持数量。记录只需足以核对去向，无须重复摘录全文。

**决定合并还是保留，先问：删去这项差异后，读者会不会改变对原因、对象、进展或支持方式的判断？**

| 检验结果 | 应怎样组织 |
|---|---|
| 存在可独立决策的业务问题，拆出后仍有完整判断 | 可独立为 Insight；若差异共同解释同一主线，则在 Reasoning 或真实分支中完整比较，不仅因对象或原因不同就强制新增条目 |
| 多项观察共同解释同一个判断，但适用条件不同 | 在同一判断的 Reasoning 中明确比较，必要时用真实多分支；不是只留一句“各地不同” |
| 一项例外会改变原判断的范围、原因或支持方式 | 先改写判断及正文解释，再安排证据；不能维持笼统判断、只在末尾补例外 |
| 仅是同一关系的重复表达，删去后诊断和选择均不变 | 合并，可压缩重复背景；保留必要来源与范围 |
| 明确提出但尚未成熟，仍有独立目标或规划意义 | 保留为有范围的提议，区分探索与已实施；不能因暂时无法评级删掉 |
| 次要、重复、范围外或实际不足以支持分析 | 可不纳入，记录具体理由；“不符主线”“篇幅短”不足以解释舍弃 |

例如，公开表达受到职业身份限制与缺少表达技能，会改变可采用的参与方式；高购买贡献、愿意经营、能独立做和能教别人，会改变选人与培养的判断。这些只是合并检验的示意，不能据此给每轮报告预装分类或事实。

总体判断少而集中，详细分析保留支撑讨论的独立发现。主次通过排序、解释关系及篇幅体现，不以删除主线之外的重要信息实现。每个二层分类可为零、一或多项，不按对称性或“一分类一条”压缩，也不为数量拆开同一个判断。只有多个分支确实共同解释一件事、需要比较且拆开会重复或失去语境时才用 Sub-insight。

成稿后从原始材料反查四部分全部二层分类，而不只检查需求。覆盖记录辅助定位，不能代替材料，以免早期笔记的遗漏继续传下去：

| 部分 | 从材料反查到正文的关系 |
|---|---|
| 经营表现与增长基础 | 不同市场的指标组合、贡献来源、预测假设与实际行为，是否被“增长承压、信心改善”遮住 |
| 卡点痛点 | 同主题内不同对象、受阻动作及原因，是否被“能力不足、需要培养”合掉 |
| 赋能需求 | 不同目标、使用者、已有供给及剩余缺口是否仍能逐项讨论；需求之间的先后与依赖是否说明 |
| 前线实践 | 做法怎样进入实际使用、谁负责、已有进展停在哪里、哪些条件影响借鉴，是否被泛化原则替代 |

对每项重要信号，在最终可读内容中找到相应业务解释。高层判断可在标题和 Summary，具体城市、人群、原因、条件及局部反例可在 Reasoning 或真实 Sub-insight 中完整展开，同样算完整覆盖；具体需求在正文及供需评价中可辨认。不因没有独立标题、未复现某个数字或某个例子而扣减覆盖。只有关键词、引文、未渲染字段或 Follow-up 问题，不算保留了业务含义。不同入口可引用同一核心分析，但引用要说明它对本处的作用。

被合并的信息，核对关键对象、数字关系、时期、条件和原始解释仍可辨认；不纳入的内容，核对理由是否成立。只有来源真实不等于综合完整；只有主题覆盖也不等于独立问题已覆盖。发现关系丢失时恢复解释或重新拆分，必要时改写主线。无法读完的材料如实限定范围。

##### 合并时检查业务机制与差异

合并候选 Insight 时，继续追问：哪些对象表现相似，原因却不同，因此不能用同一种支持回应？依次核对材料是否指向同一业务机制，合并是否丢失不同对象的约束与支持选择，是否有改变适用范围的反例，以及是否混用了不同项目或不同阶段的结果。

删除检验以业务含义为准：去掉这项信息后，是否会改变对问题、原因、适用范围或支持方式的理解？会改变就恢复其解释；只是同一机制的同义例子可以合并。保留共同主线时，分支机制与条件仍在 Reasoning 中比较；确有两个以上真实分支、分开阅读有助理解时才使用 Sub-insight。可以在一段 Reasoning 中完整说明的差异，不为增加覆盖而另造层级。

城市与人群比较保留的是判断意义，不是数字清单：数量不足、持续购买不足、现有伙伴单位产出下降，需要的支持可能不同；基层缺方法与基层愿意改变但头部未安排任务和带教，也不能都落成继续培训基层。相似表象不等于共同根因。

局部正向案例要参与解释条件。伙伴开始做海报、排课或在后续月份接手部分任务，能够说明已能承担什么、前期支持提供了什么、何时可减少员工介入以及哪些支持仍须保留。把这些进展用于调整接续判断，不放大成整个市场已自主运营，也不因总体仍有困难而省略。

#### 重要信息必须有可见去向

呈现层级执行 综合判断要求：重要业务含义可在主判断、业务推理、真实子判断或具体需求中完整解释；实践结果与条件进入 Reasoning，原始支持进入 Evidence，不另开案例层。是否覆盖按读者能否理解差异及支持含义判断，不按标题数量判断。

不要求所有信息都生成主条目，也不能仅因材料在引文中出现就视为洞察已覆盖。以下要求约束生成过程与最终内容，结构、引用或渲染通过不能代替。报告组织见 报告组织与展示要求。

### 1. 区分事实、解释和建议

例如：

“新人下降”是业务现象。

“因为年轻人都不愿意创业”是受访者提出的一种解释。

“公司需要做年轻人OPP”是可能的解决方案。

三者不能直接画等号。

优秀分析者必须追问：有没有证据证明年轻人创业意愿下降是关键原因？是否也存在现有事业价值表达不适配、开口方式老化或承接不足？

这能避免把前线的第一反应直接当作根因。

##### 理解发言与推断边界

同一句话可能包含观察、原因解释、预测和期待。先拆清这些内容各自是什么，再决定它能支持什么判断；不能因发言很肯定，就将其中的解释当作已证实原因。

#### 判断这段发言提供了什么

片区座谈不是标准问卷：有人擅长业务拆解，有人更能描述实施细节，有人首先说前线感受，有人习惯直接提公司该做什么。这些输入各有用途，不能等权搓成共识，也不能只留下善于分析和表达的人的观点。判断的是当前这段话的证据与解释能力，不是给发言人、片区或职位评高低。相同的人在不同主题可以提供完全不同的信息。

#### 区分观察、归因、体验与期待

| 这一段在提供什么 | 具体表现与可以支持的分析 | 还需要辨认什么 |
|---|---|---|
| 业务趋势判断 | 比较本期与前期、指出人员和生产力变化，可帮助形成态势候选判断 | 是实际数据、多个市场现象、预计目标还是个人信心？“明年有把握”不证明销售将增长。 |
| 机制解释 | 说明支柱减少、本人补销售、育人时间减少如何连接，可帮助定位干预点 | 每一环有何观察？先后顺序是否成立？有没有不同条件下的反例？逻辑完整仍可能未经验证。 |
| 实践反馈 | 说明谁试了什么、哪里卡住、哪部分没起作用，可检验机制和方案条件 | 已实施还是筹备？变化发生在参与、动作还是业务结果？哪些对象退出或没受益？ |
| 前线体感与使用体验 | “材料太多找不到”“活动后不知邀去哪里”，可指出早期信号和真实使用障碍 | 适用哪些人？是资源确实缺失、交付不清、理解偏差或局部体验？体感本身有价值，但不自动证明公司供给状态。 |
| 解决方案与期待 | “再办培训”“建平台”“上 AI”，可说明对支持的期待 | 想改变谁的什么动作？现有做法为什么没满足？平台、内容或课程是不是必要，是否有更贴近障碍的回应？ |

一段可以同时含多类内容；不要求给全文打分类标签，也不要求输出质量矩阵。将具体观察、发言者归因、预期和已验证结果分开理解，并在报告用不同措辞体现。

#### 同一句评价可能有不同解释

情境 A：发言人只补充“环境不好，大家都没有动力”。可以保留为其感受到的压力；尚不知道谁减少了什么动作、从何时发生，不能据此写成“外部经济导致基层行动力下降”，也不能自动开出激励课程。

情境 B：发言人进一步说“以前固定活动有人组织，伙伴持续参加；活动减少后，没有形成独立行动习惯；领导人同时把精力转回自己目标，伙伴没有后续反馈，也没有能承担的小角色”。这提供对象、行为、时点、角色与机制线索，适合形成“持续反馈和角色承接可能不足”的候选判断。

若没有独立的观察验证，仍写“发言者将其归因于……”或“材料提示可能……”，而不是宣布根因已确定。

若后文补充“固定活动恢复后，只有一部分重新参与；另一部分因家庭照护退出”，应保留差异，修正统一机制；不能为了让闭环好看，删掉不能被该解释涵盖的人。反过来，一个人说不清机制，不意味着其家庭照护或资源使用困难不真实。

#### 结合追问后的澄清修正理解

“为什么新人减少？”—“因为新人难找”只是重述现象，没有解释原因。若进一步说“原来的熟人介绍变少，社群成员仍是老顾客；线上报名增加却没有后续邀请”，才把问题具体到渠道和承接动作。仍应区分熟人渠道下降、线上初步接触和后续失联，不把它们都塞进“联系新人能力不足”。

“需要更多案例”—“现有案例不少，但都是高职级伙伴的成功结果，看不到同层级的人怎样完成第一步”，对原诉求作了修正。若后文又说已有基层案例但无法搜索到，需求还应从“制作更多案例”进一步转向“发现和交付合适案例”。优先使用完整对话中最终得到支持的理解；不要凭最后一句就否定前文所有体验。

被问到后不断重复“就是没有意愿”，解释力没有因此增强；被问到后承认“我们还没做，所以不知道”，虽然证据有限，却帮助准确界定它是设想。对质疑的承认、例外、失败和修正值得保留，不能只摘自信且好看的结论。

#### 区分设想、实施与实际效果

“觉得可能有效”是设想；“准备开展”是方案；“已经开始”证明实施；“一部分有效、一部分没效”提供差异反馈；“知道在什么条件下有效”提供可迁移的候选解释。阶段越后可以支持的问题越多，但不意味着结论必然更可靠：声称“知道为什么有效”仍要有实际依据，早期失败也未必足以否定一个机制。

例如，活动来了很多人但后续没来：可能是邀请断了、客群不适配、安排成本高，也可能首次体验就没有价值。要看资料里到底观察了什么。有人承认“没有安排后续邀请”，只证明这一步未发生，不足以保证补邀请后就能留存；有人说“我们联系过但多数因时间冲突没来”，则会改变优先支持方向。失败案例比未拆解的成功口号多给了线索，但仍需要分清原因是解释还是已验证。

### 把已成立的认识组织进现有报告

##### 原文摘录与来源

正文负责解释，原话负责让读者核对依据。选取与当前判断相关的内容，清理口头冗余，同时保留影响原意的对象、数字、否定、条件和实施状态。

#### 选取相关原话并保留限定

完整理解原文后，选取支撑当前判断的相关内容，清理后直接展示。Evidence 区保留具体信息、例子和有意义的表达，不把周边长对话整段搬入，也不继续压缩成分析总结。

- 去掉语气词、口头重复、寒暄、无关插话和旁支，适当理顺混乱语序；无需逐字保留每个措辞。保留对象、角色、数字和单位、条件、否定、程度、不确定性，以及“已做／正在试／计划做”的区别。
- 保留与判断相关的具体限定、例子及有意义的比喻。清理口头冗余不能把具体原话改成概念总结；总结与综合判断放在正文。
- 右侧只展示清理后的内容，不加“节选并清理口头重复”“跨段节选”“说话人1”“说话人2”等编辑或人工编号标记。几个相关片段可分为短段，文件名及各实际段落、页码或时间定位继续显示；跨段定位列出实际位置，不用连续范围掩盖中间未引用部分。
- 不改变不同发言者的原意，不把追问中的假设改成受访者认可的事实。不同文件或发言分别登记相应证据与定位，不编发言人姓名，不为了串成一句话补写因果或结果。关键业务术语转写有歧义时，不能在引号中悄悄改成确定含义；先回查上下文，仍不清楚则保留疑点或改用无歧义片段，解释放在分析文字中。
- 不设统一字数或条数，不以自动截断、隐藏溢出或删掉关键限定来缩短证据区。长段包含多个问题时，只选当前相关部分，其余重要信息在合适判断下保留。案例、假设和供需评估引用的证据同样执行。

交付前逐项展开资料依据，核对每段是否支持当前信息点、具体内容是否保留、是否混入无关对话、定位是否准确，以及清理是否改变原意。长段若含多个独立问题，选出当前相关片段，其余重要信息在合适判断下保留。不设统一字数或条数，不通过截断、隐藏溢出或删除关键限定来缩短证据区；内容需要时可保留较长的相关摘录。供需表、假设和案例内的证据同样执行。

### 材料与依据

先确认每种材料能说明什么。例如，正式政策可以解释规则，本轮访谈可以说明当地如何使用规则；政策本身不能证明当地已经产生效果。这个区别决定后面的判断能依据哪些信息。

##### 区分材料的证明范围

| 资料 | 可以做什么 | 不能做什么 |
|---|---|---|
| 本次原始访谈 | 支撑实际观察、发言者解释、明确诉求和前线实践 | 未提及不能写成不存在；观点不能直接变成已证实因果 |
| 原稿及其合并稿 | 帮助完整理解与定位 | 同一转述不得重复计为独立支持 |
| 正式战略、政策 | 支撑适用版本的方向、制度及条款 | 证明某市场已采用或有效 |
| 正式指标 | 支撑对应时期、范围、口径的数值 | 自动证明原因或访谈中的机制解释 |
| 术语、业务关系、地域映射 | 解释概念、身份和范围 | 创造当前市场事实 |
| 画像与访谈质量资料 | 帮助提出比较问题，识别覆盖限制 | 用画像标签替代当地事实，或按质量机械排除异议 |
| 评估用参考报告、评分题库、历史完整输出 | 仅供报告固化后的外部评估 | 不作为报告生成或自查输入，不读取其中答案来补齐当前输出 |

需要精确数字、政策门槛或历史原文时，读取本轮实际提供的正式资料。术语、战略时期及资料适用条件见[业务背景](../../knowledge/K1.md)。

##### 当前分析使用哪些输入

依据本轮原文形成判断，按通用分析、写作与质量要求检查推理与表达。运行时只使用本轮访谈、允许的业务背景及当前生成规则；不读取完整参考报告、历史生成结果或评分答案来模仿内容。

##### 历史判断视角的使用条件

以下是历史材料与手册启发的判断视角，不是本次应当重复发现的结论。只在本次材料有依据时采用；相反证据同样需要认真解释。

顾客接触和持续关系的具体判断见[顾客业务逻辑](../../knowledge/K2.md)；独立经营、带教和组织责任的具体判断见[伙伴与组织逻辑](../../knowledge/K2.md)。

##### 校准例只说明方法

本 Skill 中的分类与表达例子用于说明分类和改写方法，不证明本轮存在这些需求或业务事实。评估用参考报告、历史报告和评分答案按本文件的材料使用边界处理；生成时使用已提炼的规则，不读取答案补结论。

##### 综合与覆盖共同执行

综合判断的目标与信息层级，须与完整阅读与覆盖部分共同执行：重要信号先识别，再综合；层级用于组织信息，不能成为删掉独立业务判断或需求的理由。完整覆盖不等于平铺，也不等于最少主条目。具体业务结论只来自本次材料，不从本文件预装。

### 来源范围、向上聚合与阅读覆盖

来源文件名、身份信息和正式地域目录共同确定材料范围。已确认六份访谈的范围见[来源映射](../../knowledge/data/source-geography-profiles.json)，只对显式选择的材料批次生效；历史英文名相同不能证明地域未变。来源于片区／大群、未细分城市的反馈属于该范围并进入上级营运区，不要求正文重复写出营运区名。来源范围、案例发生地和结论适用范围分别核对；跨地区案例须显式标注，不能沿来源范围误当当地事实。

地域可向上汇总，不向下泛化。城市证据可进入上级综合，片区共性不自动分配到每个城市。无独立城市材料只说明“尚不足以形成独立判断”，不能写成没有问题、没有需求。地名使用正式名称，不以负责人称呼代替片区／大群名称。

只有用户明确要求局部或阶段分析时，才可按约定范围交付部分材料报告。用户要求完整报告而尚未读完时，必须继续阅读与综合，不得自行缩小范围或以阶段稿结束任务。可给明确标为未完成的进度或预览，但须继续完成全文报告。材料量大、已有足够洞察、时间或上下文压力、生成器通过均不是完成依据。确实无法读取或被外部条件中断时，说明具体未完成文件／区间、原因及继续所需条件，不宣称完成。局部报告在 scopeLabel 及交付说明中标明范围，不新增报告提示区。未提取到不等于不存在。该要求是对实际工作的陈述，不能把某份历史阶段稿的阅读状态预设到后续所有报告。

## Quality Checks
原文、位置和上下文可核对；人名不猜；标准化不覆盖原文；完整阅读状态不得由提取成功推断。

- 核对原稿实际内容与本项产出，保留对象、动作、数字、条件、实施状态和来源。
- 事实、受访者解释、分析推断、明确请求和行动建议分别可辨；未知不补成确定结论。
- 从材料反查重要信息的可读去向，再从结论回查证据；仅有引文、主题名或内部字段不算完整解释。
- 对照K5的事实、范围和质量标准完成检查，结构或计算通过不替代业务判断。
